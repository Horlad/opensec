OpenCode supports command traffic proxying through the TUI `/proxy` command and custom certificates for enterprise network environments.

---

## Proxy

OpenCode keeps its own LLM/API requests direct.
Only code and CLI command execution traffic is proxied.

Use `/proxy` from the TUI:

```bash
# Show current command proxy settings
/proxy

# Set proxy for command execution
/proxy http://proxy.example.com:8080

# Set bypass list for command execution
/proxy no localhost,127.0.0.1

# Disable command proxying
/proxy off
```

`/proxy` settings are persisted globally and used in both local mode and Apple container mode.
Proxy environment variables are not used as a configuration source.

---

### Authenticate

If your proxy requires basic authentication, include credentials in the `/proxy` URL.

```bash
/proxy http://username:password@proxy.example.com:8080
```

:::caution
Avoid hardcoding passwords. Use environment variables or secure credential storage.
:::

For proxies requiring advanced authentication like NTLM or Kerberos, consider using an LLM Gateway that supports your authentication method.

---

## Custom certificates

If your enterprise uses a private CA, use `/cert` in the TUI to manage trusted command certificates.

```bash
# Open certificate manager menu
/cert

# Install CA from pasted PEM body
/cert
-----BEGIN CERTIFICATE-----
...
-----END CERTIFICATE-----

# Install CA from attached prompt file
/cert @certs/internal-ca.pem

# Install CA from local file path
/cert /path/to/internal-ca.der
```

The `/cert` menu lets you:
- View OpenCode-managed certificates
- Add a certificate from PEM text or file path
- Remove a certificate with `ctrl+d` (press twice to confirm)

OpenCode persists managed certificates and reapplies them automatically when a new Apple-container Kali runtime starts.

On macOS host mode, certificate add/remove uses an administrative prompt so you can authorize trust-store changes with your password.
